# 协作风格与使用习惯

## 上下文
用户作为 AI 架构师，与 AI 协作的隐含契约。违反这些会被评价为「磨磨唧唧/浪费时间」。

## 要点（习惯清单）
- **必做项直接执行，不反复确认**：一旦判定为「必做/封版前必做」，绝不再塞进「待你拍板」列表去问要不要做。必做 = 直接给指令执行。
- **要「直接可复制的下一步指令」**：不要铺垫、不要反复确认。指令须精确（文件/行号/代码片段/验证口径/commit），可直接转发给执行方（TRAE）。
- **技术指令必须显式写出结构锚点层级**：涉及 Markdown 分块等按标题层级操作，必须写明是按 `#`/`##`/`###`/`####` 哪一级；UI/配置要手动核对层级的，把具体层级/字段名/位置写死，省去翻界面成本。可解释原因，但不能只给抽象描述。
- **事实准确性优先**：要求 AI 对照真实代码/文档核实并先确认状态再执行；拿不准就停问，禁止编造。
- **显式指令才推送到远程**：禁止 AI 自主推送；推送需用户明确说「推吧/继续」。
- **agent 应主动维护项目文档/状态**：不视为「顺手」任务；改动用 Playwright 实浏览器验证并报告（步骤/结果/控制台错误）。
- **云部署用户自己来**：本地 docker compose 全栈 = 云端等价物，AI 聚焦功能 + 工程化（CI/RBAC/bug/文档债）；不要把真实云部署当 AI 待办反复推。
- **工程纪律**：≤3 文件/批、分开提交、做门禁验证。
